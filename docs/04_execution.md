# ④ 操作・実行

## 目的

③が作ったメーカー非依存の操作意図を、Smart LEDZ、Qrio、SwitchBotなどの具体的な
命令へ変換し、安全に実行して結果を確認する。

## 実行前

対象機器、部屋、現在状態、利用者権限、安全条件、操作期限を確認する。鍵、火気、空調
など影響の大きな操作は、再認証、明示確認、在宅状態など追加条件を設ける。
機能ごとに機器、SumiCore、利用者のどれが管理主体かを決め、機器側とSumiCore側に
同じスケジュールや制御規則を重ねない。

## 実行中と実行後

- 同じ依頼を重複実行しない識別子を持つ。
- タイムアウト、再試行回数、総実行時間に上限を設ける。
- 要求を送ったことと、機器状態が実際に変わったことを区別する。
- 成功、失敗、不明、見送りを記録する。
- 操作意図、判断理由、対象、実行者、結果を追跡できるようにする。

## 故障時

④が停止しても①〜③と保存データを壊さない。HEDPが使えなくても、メーカー純正アプリ
や手動操作を残す。機器自身の安全機能をHEDPで置き換えない。

SumiCoreだけで実現する機能は、SumiCore依存であることと、停止時の安全な代替動作
または停止状態を定義する。安全に関係する機能はSumiCoreだけを唯一の経路にしない。

## 起動時と再接続時

- 保存済みの古い状態や未完了命令を自動的に再送しない。
- 機器から現在状態を取得し、鮮度と品質を確認する。
- 操作意図の期限、安全条件、管理主体を再評価する。
- 現在状態を確認できない機器は操作せず、結果不明として記録する。
- 状態同期が完了してから、新しい操作意図の受付を再開する。
