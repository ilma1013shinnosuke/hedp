# HESTIA共通イベント配達契約

## 決定

Adapterがイベントまたは観測を取得したら、必要なアプリ内処理へ先に配達する。
保存、集計、分析、Raw転送、監査ログの完了は待たない。これは照明だけでなく、
HESTIA全体と今後のAdapterに適用する。

```text
Adapter
  ├─ 即時経路 → アプリ内イベント処理 → 判断 → ExecutionGate
  └─ 非同期経路
       ├─ 履歴保存
       ├─ 集計
       ├─ Raw転送
       └─ 監査ログ
```

HIKIDASHIは開発凍結中のため、この経路の実装先にも必須依存先にもしない。
KURAや外部アーカイブが停止しても、HESTIAの即時経路は動作または明示的に
安全停止できなければならない。

## 即時経路

- 取得後、保存処理より先に登録済みの処理へ配達する。
- 情報源ごとの連番で到着順を検査する。
- イベントIDで重複を排除する。
- 処理時間に上限を設ける。
- 失敗、時間切れ、順序違反を成功扱いしない。
- 時間切れは結果不明とし、危険な操作を自動再送しない。
- 操作は必ず既存のExecutionGateと結果確認へ渡す。

## 非同期経路

- 保存、集計、Raw転送、監査は用途別の独立した有界キューへ入れる。
- 即時配達中に非同期処理の実体を呼び出さない。
- キュー満杯は`backpressure`として明示し、黙って成功扱いしない。
- 失敗時の再送回数には上限を設ける。
- 再送上限後は`retries_exhausted`として残す。
- キュー混雑や保存障害を理由に即時経路を待たせない。

## 最初の実証

SwitchBot通常人感センサーの正常な検知イベントを即時経路へ渡し、
`MotionLightingAutomation`がSmart LEDZ向けのシーン／スケジュール選択意図を
生成する。並行して同じイベントを保存用キューへ入れるが、保存の実行や完了を
待たずに照明判断が完了することをテストする。

実機送信は別段階であり、現在は行わない。Smart LEDZのスケジュール選択は
実機コマンドとread-backが未検証であるため、Execution層で安全停止する。
