# Eufy屋外カメラによる日照観測

最終更新: 2026-07-27
対象候補: Eufy SoloCam E42 2-Cam Kit + HomeBase
運用状態: `research`（実機未接続）

## 目的

庭カメラの映像監視とは別に、必要な時だけ取得した1枚の画像から、屋外の相対的な明るさと
塀に現れる影の強さを観測する。発電・積雪・融雪の判断材料にはできるが、このAdapterだけで
天気、積雪、発電量を断定しない。

## 境界

```text
カメラ固有の1枚取得
  ↓ RgbFrame（最大幅640、メモリ内のみ）
純Pythonの日照証拠解析
  ↓ illumination_index / shadow_contrast / quality
共通Observation
  ↓
第2層の保存・集約（別実装）
```

- `reader.py`は1枚を読み取るだけで、カメラ操作を公開しない。
- `opencv_reader.py`はOpenCVを任意依存として遅延読込する。HESTIAコアはOpenCVへ依存しない。
- `analysis.py`はカメラ、RTSP、OSを知らない純Pythonである。
- `collector.py`は総試行回数を最大2回、1回の待ち時間を最大30秒に制限する。
- 認証情報を含み得るRTSP URLと例外本文は、結果、repr、ログへ出さない。
- 画像は解析後に保存しない。通常保存するのは相対指標、品質、時刻、試行回数だけである。

## 観測値

- `illumination_index`: 空または明るさ基準面の相対輝度。0〜1で、luxではない。
- `shadow_contrast`: 塀など固定面の明暗差。0〜1。
- `clipped_fraction`: 黒つぶれ・白飛びに近い画素の割合。露出条件の診断用。
- `state`: 現地校正後だけ`direct_sun`、`diffuse_light`、`low_light`を推定する。
- `quality`: `good`、`missing`、`invalid`、`unknown`等の共通区分。

カメラの自動露出、HDR、ISO、シャッター速度、絞り、画像処理により、画像の明るさと実際の
照度は一致しない。校正前の`state`は`unknown/site_calibration_required`とし、絶対luxを
生成しない。

## カメラ配置

- 空だけでなく、位置が変わらない塀の一部を同時に画角へ入れる。
- 太陽を直接入れず、雨雪がレンズへ当たりにくい北寄りの軒下等を候補とする。
- 影を見る範囲と明るさを見る範囲を正規化ROIで別々に指定する。
- 季節、積雪、落葉、汚れ、夜間照明でROI条件が変わった場合は再校正する。

## 負荷方針

常時配信や常時録画は使わない。初期候補は日中5〜15分に1枚、天候変化時だけ短時間隔とし、
実機のバッテリー消費とRTSP起動可否を確認してから決定する。解析幅は既定320pxで、2017年の
Intel Macでも1枚単位の処理に限定する。

## 太陽光・蓄電池に応じた取得抑制

カメラAdapter自身はFusionSolarへ接続しない。正規化済みの発電・蓄電池・予測値を受け取る
純Pythonの取得ポリシーが、`acquire`、`skip_high_generation`、
`pause_energy_scarcity`のいずれかを決める。これにより機器固有通信を混ぜず、Linux/Windows
への移行時も同じ判断を再利用できる。

`collect_if_energy_allows()`を正式な接続点とし、判断結果が`acquire`以外ならReaderを
呼び出さない。省略時には架空のカメラ観測を生成せず、「なぜ接続しなかったか」という
判断記録だけを残す。自動試験では、発電十分時と冬季電力不足時のReader呼出回数が0回、
取得許可時が1回であることを確認する。

初期値は次のとおり。すべて設定値であり、3週間以上の観測後に家庭の実績から見直す。

| 判断 | 初期値 | 理由 |
|---|---:|---|
| 大量発電として撮影省略 | 定格AC出力の70%以上が10分継続 | 一時的な雲間発電で省略しない |
| 発電根拠の鮮度 | 2分以内かつ`good` | 古い値で「晴れ」と断定しない |
| 冬季の省エネ停止 | 蓄電池30%以下 | 必要電力をカメラより優先する |
| 冬季の省エネ停止 | 残り発電予測－必要電力予測が-2kWh以下 | 曇天継続の不足見込みを反映する |
| 停止からの再開 | 蓄電池40%以上 | 10ポイントのヒステリシスで往復を防ぐ |
| 予測による再開 | 残り収支が+2kWh以上 | 小さな予報変化では再開しない |
| 不確かな発電情報 | 60分後に低頻度取得 | 大量発電とは扱わず、負荷も抑える |
| 停止中の再評価 | 60分ごと | カメラを起動せずエネルギー情報だけ確認する |

現在の4.95kW定格を基準にする場合、70%は約3.47kWである。ただし入力値がAC出力ではなく
DC発電量や蓄電池充電込みの処理電力なら、その値に対応した定格を別設定にする。発電が多い
場合の省略は「画像を見なくても晴天の証拠が十分」という判断であり、冬の停止は
「観測価値より節電を優先する」という別の判断である。

停止状態では、蓄電池または予測収支が回復した証拠を得るまで停止を維持する。欠損、古い値、
品質不明を回復証拠として使わない。カメラ取得を停止しても、太陽光・蓄電池の収集は継続する。

- RTSP開始・停止による電池消費と復帰時間。
- 実際の画像に適したROI、撮影間隔、校正閾値。
- 夜間照明、雨、雪、レンズ水滴、HDRによる誤判定率。
- 70%・30%・2kWhの初期閾値が、実際の発電曲線とカメラ消費電力に対して適切か。
- 第2層での通常保存期間と、異常時だけ保持する診断画像の承認手順。

上記は実機適格性確認で測定する。カメラ登録、ネットワーク変更、RTSP有効化、録画設定変更は
このオフライン実装の範囲外である。

## 実機到着前に完成しているもの

- RTSPやカメラSDKへ依存しない純Pythonの日照解析
- 模擬画像による校正前・校正後・欠損・異常値の試験
- 発電量・蓄電池残量・予測収支による取得省略／省エネ停止
- 取得省略／停止時にカメラへ接続しない強制ゲート
- RTSP URLを設定ファイルへ書かず、環境変数名だけを持つ設定形式
- URL、家庭固有ID、画像、例外本文を含まない匿名診断結果
- 1回30秒以下、最大2試行という上限

設定例は`config/examples/eufy_weather.example.json`に置く。これはGit管理可能だが、
実際のRTSP URL、認証情報、家庭固有IDは書かない。

実機なしの確認例:

```bash
.venv/bin/python scripts/qualify_eufy_weather.py \
  --config config/examples/eufy_weather.example.json \
  --fixture tests/fixtures/eufy_weather/direct_sun_anonymous.json
```

実機導入後は、RTSP URLを`.env`等から実行時だけ環境変数へ読み込み、次の1回取得を使う。
コマンド出力にはURL、画像、認証情報を含めない。

```bash
.venv/bin/python scripts/qualify_eufy_weather.py \
  --config config/examples/eufy_weather.example.json \
  --live-read-only
```

## 実機導入日に埋める項目

1. E42とHomeBaseで、必要時だけ1枚を取得できるか
2. 取得開始から1枚受信までの時間と、電池消費
3. 空・塀・影を見るROIの位置
4. 晴天、薄曇り、曇天、雨、積雪、夜間照明の実測サンプル
5. 自動露出・HDR・水滴・汚れによる誤判定
6. 現地校正の3閾値
7. 5〜15分間隔と、発電量による取得省略が電池寿命へ与える効果

ここまでを実測してから`research`を`qualified_read_only`へ変更する。カメラの交換時は
Readerだけを差し替え、解析、取得ポリシー、保存契約は再利用する。
