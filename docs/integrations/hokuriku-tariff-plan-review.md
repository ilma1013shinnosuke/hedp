# 北陸電力プラン定期確認

## 目的

現在契約が家庭の実績に適しているかを、半年ごとに直近12か月で比較する。
年1回は24〜36か月の季節差と実請求との差も精査する。料金改定を検知した場合は、
影響期間だけ臨時再計算する。契約変更は自動実行せず、候補、年間差額、根拠、品質を
利用者へ提示する。

## FusionSolarの加工データ

日次energy-balanceが返す `totalProductPower`、`totalSelfUsePower`、
`totalOnGridPower`、`totalBuyPower`、`totalUsePower` を日別正本とする。
5分値は日計の代用品にせず、時間帯別料金の配分と日計照合に使う。

- 日別: 発電、自家消費、売電、買電、消費
- 5分別: 意味と単位を実機適格性確認済みの系統買電系列だけをkWhへ積算
- 月別: 日計の合計と、5分値から作る時間帯別買電量
- 品質: 日計の欠損と5分内訳の欠損率を別々に保存
- 通常保存: 日別正本は5種類のkWh値を保存する。検証済みの5分値系列が
  ある場合だけ5分内訳coverageも保存する。月別は買電量、coverage、
  内訳件数を既存の `Record` 形式で保存可能にする
- 禁止: 欠損を0や前回値で埋めない。未確認のRawキーを推測で買電に割り当てない

この加工は日ごとに最大288点を一度足すだけであり、画像解析や大量Raw再読込を
伴わない。毎日の収集直後に作成し、月次・半年・年次レビューで再利用する。
日別の正確な値は5分値から復元せず、FusionSolarの日次energy-balance値を採用する。
5分値が未設定・未取得の場合をcoverage 0%として記録しない。
日次の定期処理、期間取得、再構築、欠損補完はいずれも同じ日別サマリー生成処理を
通るため、通常運用でも検索可能な日別値が自動保存される。

## 料金データ

公開料金、燃料費調整、再エネ賦課金、政府支援、将来の約款改定は公開情報から取得し、
適用期間と公式出典を残す。公開情報の取得に認証は不要である。個別請求との照合を
将来行う場合のみ、ほくリンクの認証Readerを別経路として設計する。

## 判定規則

- 半年ごと: 直近12か月。季節偏りを避ける正式比較
- 年1回: 直近24〜36か月、将来料金、感度、実請求差を詳細監査
- 料金変更時: 影響期間のみ臨時再計算
- 12か月未満、料金が古い、加入条件不明、時間帯内訳のcoverage不足では断定しない
- 受付終了プランは現在契約の比較基準には使えるが、新規候補にはしない
- 推薦結果から契約変更を自動実行しない

## 現時点の境界

計算、日別・月別集約、周期判定は純粋PythonでOS非依存とする。本番DB、launchd、
外部HTTP取得への接続は、料金抽出と買電5分系列の適格性確認後に別工程で行う。
