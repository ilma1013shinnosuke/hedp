# FusionSolarオプティマイザー読み取り

## 目的

Huaweiオプティマイザーの5分値を、積雪、部分影、融雪進行、個別故障の判定材料として
読み取る。瞬時制御には既存のModbusレジスタ値を使い、本データは診断、予測、
長期学習に使う。

## 根拠と現在の確認段階

Huawei `SUN2000LB V300R024C00 Modbus Interface Definitions` Issue 04
(2025-06-13)の4.2および6.3.7.1を根拠とする。

- Huawei独自function: `0x41`
- ファイル種別: `0x44`
- ファイル版: `V101`
- 同期・保存間隔: 5分
- 転送: 開始`0x05`、データ取得`0x06`、完了`0x0c`
- busy応答: 10秒後、最大6回まで再要求
- 実装段階: `implementation-confirmed`
- 実機段階: `blocked`
  - 2026-07-26、通常のインバーター値を正常取得できる同一Modbus TCP経路で確認した。
  - `0x44`の開始要求は、発電停止中・発電中の双方で一貫して`no_permission`となった。
  - 通信アドレス`0`〜`247`を低速・各1回の読み取り専用で確認した。到達できた
    インバーター候補は1台だけで、その候補でも同じ結果だった。
  - 通信断、宛先IPの誤り、夜間停止による失敗ではない。
  - SmartLogger WebUIからオプティマイザー検索を完了したが、合計、オンライン、
    検出済みの各台数はいずれも0だった。検索後もModbus応答は変わらなかった。
  - WebUIの登録構成は電力計とインバーターの2台だけで、ExpansionModuleも0台だった。
    オプティマイザーの登録行は存在しない。
  - 取得した設備ログの利用者操作履歴には検索開始が1件だけあり、完了、検出台数、
    過去の登録を示す記録は見つからなかった。
  - SmartLoggerは`V300R023C00SPC152`系列、インバーターは
    `V200R001C00SPC142`系列であることを確認した。個体識別情報は記録しない。
  - SmartLoggerは公式マニュアルのV300R023世代に該当する。より新しいSPCが存在するが、
    更新によって本件が解消する公式根拠は未確認のため、ファームウェアを変更しない。
  - 実際に対応オプティマイザーが設置されているか、型式、台数、配線、登録状態を
    施工資料または保守会社で確認する必要がある。

公式資料:

- https://support.huawei.com/enterprise/en/doc/EDOC1100480329
- https://info.support.huawei.com/enterprise/en/doc/EDOC1100366800/
  426cffd9/about-this-document

## 取得項目

オプティマイザーごとに次を読み取る。

- 出力電力
- 対地電圧
- alarm bitfield
- 出力電圧・電流
- 入力電圧・電流
- 温度
- 運転状態
- 積算発電量

プロトコル上の論理アドレスと応答順の`local_index`をローカルDBへ保存する。
論理アドレスは外部へ表示しない。シリアル番号を含む別ファイルは取得しない。
実機で順序と論理アドレスの安定性を確認できるまでは、パネル配置との対応を推測しない。

## 安全境界

- 通常のModbus書込みfunctionを実装しない。
- `0x41`は、機器からクライアントへファイルを送る開始、データ取得、完了だけ許可する。
- IP、シリアル番号、SSID、MACアドレスを出力・保存しない。
- `0x45`の機器情報ファイルはシリアル番号を含むため、現段階では収集しない。
- 実機初回確認では設定変更、device search、positioning、firmware更新を行わない。
- WebUIのソフトウェアアップグレード画面では、更新ファイルを選択・送信しない。
- 初回実行前に、対象が現在の読み取り限定SmartLoggerであることを確認する。

## 保存方針

初回の適格性確認では、取得時刻、5分時点、オプティマイザー値、CRCと、再解析用の
完全な`0x44`ファイルを同じRawData内へ保存する。別のRaw行には複製しない。
通常運転へ移す場合は次を再検討する。

- 日照時間帯のみ5分値を残す。
- 夜間の同一値は連続区間へ集約する。
- alarm、online/offline、急変はイベントとして残す。
- 長期学習にはパネル別の日次集計と積雪・融雪イベントを残す。
- 一般的な定期Rawを永久保存しない。

## 初回確認手順

1. 全テストと静的検査を通す。
2. SmartLoggerと対象機のfirmwareが公式仕様の対象範囲か確認する。
3. `collect-optimizer`を手動で実行する。拒否時の自動連続再試行は行わない。
4. 秘密値を表示せず、snapshot数、台数、時刻、範囲、構造だけを確認する。
5. DB増分が1 RawDataだけであることを確認する。
6. 5分後に2回目を実行し、時刻更新と順序安定性を確認する。
7. 実機で正常取得できてから24時間のread-only観測を行い、定期ジョブへの追加可否を判断する。

現状は手動診断専用とし、定期ジョブには追加しない。`no_permission`は通信障害として
再試行せず、仕様または権限条件が変わったときに再確認する。SmartLogger、インバーター、
ルーター、保守会社管理設定は、この確認のために変更しない。

CLI:

```bash
hedp collect-optimizer
```

このコマンドは既存のModbus接続設定を実行時だけ参照する。定期ジョブにはまだ追加しない。
