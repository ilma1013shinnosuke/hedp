# 屋根・太陽光パネル積雪推定

## 採用方針

屋根の積雪推定は、オプティマイザー情報を必須条件にしない。気象、既存の発電設備観測、
将来の画像認識を組み合わせる第3層の推定機能として実装する。推定結果だけを根拠に
設備設定を変更せず、第4層へ操作意図を渡す場合は別途ExecutionGateを通す。

目的は次の3点を区別して扱うことである。

1. 今後、屋根へ積もる可能性を予測する。
2. 現在、パネルが雪で覆われている可能性を推定する。
3. 融雪の開始、進行、完了を推定する。

## 証拠の優先順位

### 1. 気象による事前予測

- 気象庁の解析積雪深、解析降雪量、6時間先までの降雪短時間予報
- 近隣アメダスの積雪深、降水量、気温、風向・風速、日照
- 現地または近隣の気温、湿度、降水

気象庁の解析・予報は約5 km格子の平均であり、屋根固有の風、傾斜、日射、落雪を
直接表さない。この証拠だけで`covered`を確定しない。

公式資料:

- https://www.jma.go.jp/jma/kishou/know/kurashi/snow.html
- https://www.data.jma.go.jp/developer/index.html

### 2. 既存PV観測による現在状態推定

日照時間帯に次を同時に評価する。

- PV1/PV2の電圧、電流、DC電力
- インバーターの有効電力と運転状態
- 同時刻、太陽高度、天気、季節に対する期待発電量
- 前日および過去の類似条件との差
- ストリング間の低下率と回復順序
- 降雪後の出力低下、気温上昇・日射後の段階的回復

夜間の発電量0は積雪証拠にしない。雨、厚い雲、停止、通信欠損、出力制御、
系統制約、機器故障を積雪と誤認しないよう、反証条件を同時に評価する。

### 3. 将来の画像証拠

屋根または庭カメラでパネル面を確認できる場合は、ローカル画像認識により
`snow_visible`、被覆率、信頼度を生成する。画像そのものの保存は必要最小限とし、
通常は判定値とモデル版だけを第2層へ渡す。プライバシー領域を撮影しない。

### 4. オプティマイザー

将来取得可能になった場合はパネル単位の追加証拠として使う。取得不能でも推定器を
停止させない。

## 状態モデル

- `clear`: 積雪なしの根拠が十分
- `snow_possible`: 気象条件から積雪の可能性あり
- `accumulating`: 積雪が増加中と推定
- `covered`: 発電設備の観測を含め、被覆の根拠が十分
- `melting`: 発電回復などから融雪中と推定
- `residual`: 部分的な残雪の可能性
- `unknown`: 証拠不足または相互矛盾

各結果には`estimated_at`、`state`、`confidence`、使用した証拠、反証、
入力の品質と鮮度、推定器バージョンを持たせる。事実と推定を混同しない。

## 収集・保存

- 気象解析・予報は元の更新間隔に合わせ、原則1時間単位で扱う。
- 日照中のPV観測は既存収集値を再利用し、積雪推定のための重複Rawを作らない。
- 推定計算は5分単位を初期候補とする。
- 第2層には状態遷移イベントと1時間集約を残す。同一状態の5分値を永久保存しない。
- 画像を導入するまでは、利用者による「屋根に雪あり／なし」の確認を学習用ラベルとして
  任意に残せるようにする。

## 導入段階

1. 最初の降雪期は観測・推定だけを行い、設備を操作しない。
2. 手動確認と照合し、誤検知、見逃し、信頼度の校正を行う。
3. 融雪完了や翌日発電可能性の表示・通知へ使用する。
4. 複数シーズンの実績後、エコキュートや蓄電池の第3層判断材料へ追加する。

屋根雪は数日残ることがあるため、単年度で固定ルールを完成扱いにしない。住宅固有の
傾向を年単位で更新する。
