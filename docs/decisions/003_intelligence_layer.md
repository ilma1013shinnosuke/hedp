# 003 情報利用・判断層の基本設計を採用する

- 状態: 採用
- 決定日: 2026-07-25

## 背景

電力、室内環境、在室、照明、鍵、空調、給湯などを横断して利用するには、メーカー別の
Adapterや操作実行とは別に、家庭として何をするべきかを決める場所が必要である。
経済性だけを最大化すると快適性や健康を損ない得る一方、すべてを利用者確認にすると
自動化の価値がなくなる。

また、欠損や古い情報、予測の不確実性、利用者の手動操作、実行失敗を扱わなければ、
同じ操作の反復、古い予約との競合、通知過多が起こり得る。

## 決定

SumiCoreの4層設計における③情報利用・判断層へ、次の基本設計を採用する。

- 安全、機器保護、利用者指示、最低限の健康・快適性を条件として守り、その範囲内で
  経済性、追加の快適性、環境性を最適化する。
- 予測範囲のすべてで得なら経済的に有利な案を優先し、損得が混在する場合は小さく
  元へ戻せる操作を短く試して早く見直す。
- 情報の品質と用途別の鮮度を判断条件に含め、欠損を0や前回値で埋めない。
- 操作ごとに、自動実行、条件付き自動実行、利用者確認、自動実行禁止を定める。
- イベント、短周期、中周期、長周期の判断を分け、待機時間と変化を無視する幅を持つ。
- 現在状態、現在の運転、機器予約、利用者指示、SumiCoreの判断を別々に管理する。
- 利用者の新しい有効な指示をSumiCoreの過去の判断より優先する。
- 実行不能や結果不明を④から受けても④に代案を選ばせず、③が再判断する。
- 系列ごとの回数、代案数、経過時間に上限を持たせ、判断と実行の無限ループを防ぐ。
- 判断しなかった理由も含め、根拠、品質、不確実性、有効期限、結果を追跡可能にする。
- 利用者の訂正を直ちに尊重し、繰り返しを確認してから設定変更を提案する。
- 通知を重要度で分け、同じ原因を集約し、継続中の同一状態を繰り返し通知しない。
- オフライン、Shadow、提案、限定自動化、通常運用の順に段階導入する。

詳細は[③ 情報利用・判断](../03_intelligence.md)を正とする。

## ④との境界

③は価値を判断し、操作意図と自動化区分を作る。④のExecutionGateは、許可、期限、能力、
鮮度、安全上の実行条件などを検査し、送信と確認を行う。④は③の価値判断を変更せず、
代案を選ばない。

通信上の上限付き再試行は④が担当し、失敗後に別の目的や操作を選ぶことは③が担当する。

## 採用理由

- 経済性と安全性を同じ点数で相殺しない。
- 情報不足時の危険な最適化を防げる。
- 利用者の手動操作と機器標準機能を尊重できる。
- 不確実な判断を小さく試し、結果から早く修正できる。
- 失敗や代案が無限に循環することを防げる。
- 判断理由と実行結果を後から比較し、改善できる。

## 影響

- ③の判断には品質、鮮度、有効期限、自動化区分、系列上限が必要になる。
- 将来は判断記録の保存先が必要になる可能性があるが、本決定だけではDBを変更しない。
- 最初の実装は一つの低リスク判断に限定し、汎用ルールエンジンを先に作らない。
- 既存の収集・診断処理を③の本番実装とみなさない。

## 採用しなかった案

### すべてを単一の点数で最適化する

安全や重大な健康リスクが小さな節約額で相殺され得るため採用しない。

### 判断ごとに常に利用者へ確認する

安全ではあるが通知と操作負担が増え、低リスク自動化の価値を失うため採用しない。

### 利用者の訂正を一度で恒久設定へ反映する

一時的な事情を好みと誤認する可能性があるため、繰り返しを確認して提案する方式とする。

### 失敗する限り代案を試し続ける

機器負荷、通知過多、予想外の操作につながるため、系列ごとの上限と停止条件を必須にする。
